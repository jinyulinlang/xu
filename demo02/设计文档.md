## 1. 总体概述
目标：为前端原型提供稳定的后端服务，支持项目/任务管理、进度更新、依赖关系、通知/预警与基础报表功能。

特性要点
- REST 风格 API（JSON），版本化（/api/v1/）
- JWT + 可插拔 SSO 支持
- RBAC（角色/项目级权限）
- 基本事件驱动通知（异步队列 + 可配置 Webhook/邮件/站内消息）
- 易于扩展的 AI 数据收集接口（事件埋点）

## 3. 详细接口定义（请求/响应 schema、示例）
通用说明
- 所有接口均以 JSON 为载体，Content-Type: application/json
- 成功响应结构：{ code: 0, data: <...> , message: 'ok' }
- 失败响应结构：{ code: <非0错误码>, error: '短错误描述', details?: {...} }
- 鼓励使用标准 HTTP 状态码（200/201/204/400/401/403/404/409/500）

鉴权示例
- 请求需在 Header 中附加：Authorization: Bearer <JWT>

示例：登录
POST /api/v1/auth/login
请求体
{
  "username": "li.jing",
  "password": "secret"
}
响应
200
{
  "code": 0,
  "data": {
    "accessToken": "<jwt>",
    "refreshToken": "<token>",
    "expiresIn": 3600,
    "user": { "id": 123, "name": "李经理", "role": "project_owner" }
  }
}

项目相关
POST /api/v1/projects
- 权限：需要 project:create 权限或管理员
请求体示例
{

  "deptId": 10,
  "ownerId": 123,

成功响应（201 Created）

GET /api/v1/projects
- 支持分页、过滤、排序
Query params: page=1&size=20&deptId=&ownerId=&status=
响应 data 列表包含：id,name,deptId,ownerId,planStartDate,planEndDate,status,completionRate

GET /api/v1/projects/:id
响应：完整项目信息，包含里程碑、统计（完成率、任务数量、风险评分 if available）

PATCH /api/v1/projects/:id
- 支持部分更新（例如更改负责人、计划时间）
- 变更需写入审计日志

DELETE /api/v1/projects/:id
- 软删除：设置 `deleted_at` 字段并保留数据 90 天（配置可变）

任务相关
POST /api/v1/projects/:projectId/tasks
请求体示例
{
  "title": "原型设计",
  "description": "交互与视觉原型",
  "ownerId": 124,
  "assigneeIds": [124],
  "parentTaskId": null,
  "planStart": "2025-09-05",
  "planEnd": "2025-09-25",
  "estimateHours": 40,
  "priority": "medium",
  "tags": ["UI","设计"],
  "metadata": {}
}
成功响应：201 + 新任务对象

GET /api/v1/projects/:projectId/tasks
- 支持 filter: status, assignee, owner, tag, overdue=true, dependencyBlocked=true
- 支持 pagination & sort by planEnd, priority

GET /api/v1/tasks/:id
- 返回任务详情：包含 history summary, dependencies list, child tasks, percentComplete, actualEnd, createdBy

PATCH /api/v1/tasks/:id
- 可更新字段：title, description, ownerId, assigneeIds, status, percentComplete, planStart, planEnd, estimateHours, actualEnd
- 约束检查：planEnd >= planStart；若变更导致冲突或依赖问题，响应 409 并提供 `conflicts` 描述
- 更新后触发 task update 事件（写入 task_updates 表 + 发布到消息队列）

DELETE /api/v1/tasks/:id
- 软删除或物理删除视策略而定（建议软删除）

任务依赖
POST /api/v1/tasks/:id/dependencies
请求体
{ "dependsOnTaskId": 23 }

DELETE /api/v1/tasks/:id/dependencies/:dependsOnId
- 移除依赖并触发依赖变更事件

GET /api/v1/tasks/:id/dependencies
- 返回依赖树或简要列表

## 4. 数据模型与数据库表设计
下列为简化关系型数据库（PostgreSQL）表结构建议，字段类型与索引供参考。

注意：所有表建议包含 `id (bigserial primary key)`, `created_at`, `updated_at`, `deleted_at`（软删除）字段。

users
- id BIGSERIAL PK
- name VARCHAR
- email VARCHAR UNIQUE
- dept_id INT
- role VARCHAR (enum: admin|project_owner|member|viewer)
- settings JSONB
- created_at, updated_at, deleted_at

departments
- id, name, parent_id

projects
- id
- name
- dept_id
- owner_id -> users.id
- status VARCHAR (enum)
- plan_start DATE
- plan_end DATE
- metadata JSONB
- created_at, updated_at
- indexes: (owner_id), (dept_id), (plan_end)

tasks
- id
- project_id -> projects.id
- parent_task_id (nullable) -> tasks.id
- title TEXT
- description TEXT
- owner_id -> users.id
- status VARCHAR (enum)
- percent_complete INT
- plan_start DATE
- plan_end DATE
- actual_end DATE
- estimate_hours FLOAT
- priority VARCHAR
- tags TEXT[] or JSONB
- metadata JSONB
- created_at, updated_at
- indexes: project_id, owner_id, status, plan_end

task_dependencies
- task_id
- depends_on_task_id
- constraint unique(task_id, depends_on_task_id)
- indexes: task_id, depends_on_task_id

task_updates
- id
- task_id
- user_id
- timestamp
- status
- percent_complete
- comment TEXT
- attachments JSONB
- created_at

notifications
- id
- type (info|warning|error)
- payload JSONB
- recipients JSONB (list of user ids or group)
- status (unread/read/ack)
- created_at

audits (optional)
- id, actor_user_id, action, target_type, target_id, diff JSONB, created_at

AI 数据埋点表（为后续模型训练储备）
- event_id, project_id, task_id, event_type, payload JSONB, created_at

## 5. 鉴权、权限与安全
鉴权策略
- 支持 JWT（短期 access token + refresh token），并留接口对接 SSO/OAuth 企业登录
- Token 签名采用 RS256（公私钥）或 HS256（共享密钥）依据运维选型

权限模型（RBAC + 项目级覆写）
- 全局角色：admin
- 项目级角色：owner, editor, viewer
- 权限表（可扩展）：resource(项目/任务), action(create/read/update/delete), role
- API 在关键写操作前进行权限检查（403）

安全要点
- 所有输入进行严格校验与转义，防止 SQL 注入/JSON 注入
- 文件/附件存储使用私有存储（S3），并生成受限访问 URL
- 强制 TLS
- 敏感日志脱敏
- 速率限制（API 网关或 Nginx 层面）

## 6. 事件、通知与 Webhook 设计
异步架构
- 使用消息队列（RabbitMQ / Kafka / Redis Streams）处理耗时任务：通知发送、预警计算、AI 事件上报
- 写操作（如任务更新）触发事件（task.updated）并入队处理

事件模式（示例）
- task.created
- task.updated
- task.status_changed
- task.dependency_changed
- project.milestone_missed
- notification.sent

事件消息体（示例 task.updated）
{
  "eventType":"task.updated",
  "timestamp":"2025-10-02T08:00:00Z",
  "data": {"taskId":123, "projectId":45, "changes": {"status": {"from":"待开始","to":"进行中"}}, "actorId":124}
}

Webhook 设计
- 用户可在系统设置中注册 Webhook endpoint（url + secret + eventFilters）
- 发送签名头（X-Signature）以便第三方验证

实时（可选）
- WebSocket 或基于 socket.io 的实现：用于实时通知、协作光标/锁定提示
- 客户端连接后订阅资源（projects:45, user:124）

## 7. 校验、边界条件与异常处理
常见校验
- 时间一致性：planEnd >= planStart；actualEnd >= planStart
- 依赖校验：无环（检测算法）；如果跨项目依赖需额外权限
- 权限校验：写操作前必须检查 user 在项目内角色
- 输入长度/类型验证

错误码示例（业务）
- 1001: AUTH_INVALID_CREDENTIALS
- 1002: AUTH_TOKEN_EXPIRED
- 2001: PROJECT_NOT_FOUND
- 2002: TASK_NOT_FOUND
- 3001: VALIDATION_ERROR (details)
- 3002: DEPENDENCY_CYCLE_DETECTED
- 4001: PERMISSION_DENIED
- 5001: INTERNAL_ERROR

并发与一致性
- 在关键更新（如 percent_complete 或 status）使用乐观锁（updated_at 或版本号）避免 lost update，返回 409 on conflict
- 对于依赖图复杂计算，采用异步重算或限流以避免查询阻塞

## 8. 性能、索引与扩展建议
索引建议
- tasks(project_id, status, plan_end)
- tasks(owner_id)
- task_dependencies(task_id)
- task_updates(task_id, timestamp DESC)

缓存策略
- 使用 Redis 缓存热点项目/任务详情（TTL 30s-5m 根据更新频率）
- 仪表盘/报表结果可采用预计算和异步刷新

扩展性
- 微服务/模块化：核心 API、通知服务、报告/ETL、AI 服务分离
- 消息队列解耦高并发操作

容量估算与分层
- 初期可用单实例 PostgreSQL + Redis 缓存；当任务数/用户增大时考虑读写分离或分库分表

## 9. 部署与运维建议
容器化
- 每个服务（api, worker, websocket, migration）使用 Docker 镜像
- 推荐 docker-compose / Kubernetes 部署

环境变量（示例）
- DATABASE_URL=postgres://user:pass@host:5432/db
- REDIS_URL=redis://host:6379
- JWT_SECRET_PRIVATE=/path/to/private.key
- S3_BUCKET=...
- SMTP_HOST/SMTP_USER
- RABBITMQ_URL

示例 docker-compose (简化)
```
version: '3.8'
services:
  db:
    image: postgres:15
    environment:
      POSTGRES_DB: app
      POSTGRES_USER: app
      POSTGRES_PASSWORD: secret
    volumes:
      - db_data:/var/lib/postgresql/data

  redis:
    image: redis:7

  api:
    image: yourrepo/project-api:latest
    ports: ["8000:8000"]
    environment:
      DATABASE_URL: postgres://app:secret@db:5432/app
      REDIS_URL: redis://redis:6379
    depends_on: [db, redis]

  worker:
    image: yourrepo/project-worker:latest
    environment: {...}
    depends_on: [db, redis]

volumes:
  db_data:
```

监控与告警
- 指标：请求延迟、错误率、队列积压、通知失败率
- 使用 Prometheus + Grafana + Alertmanager
- 日志集中：ELK / OpenSearch

备份策略
- DB 日备、每小时 WAL 归档
- 定期演练恢复

## 10. 开发与演进注意事项
- API 版本化：任何不兼容变更需增加 /v2 套件
- 数据迁移：使用工具（Flyway / Liquibase / Prisma Migrate）保证迁移可回滚并记录
- 测试覆盖：单元测试、集成测试（数据库）、端到端测试（模拟用户流）
- 性能测试：对重负载场景（批量更新、依赖重算）做基准测试
- 隐私合规：对敏感人事数据提供删除/导出接口，满足合规需求
